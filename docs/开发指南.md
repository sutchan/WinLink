# WinLink 开发指南

本文档面向希望本地运行、构建或参与 WinLink 开发的贡献者。环境要求与命令以仓库根目录 `README.md` 为权威来源，本文档补充更具体的开发约定与流程。

## 环境准备

- **Node.js** 18+ 或 **Bun** 1.0+
- Windows 为推荐的目标使用场景；当前 Web 原型可在任意平台运行开发服务器
- 推荐编辑器：Visual Studio Code + ESLint / Prettier / Tailwind CSS 插件

## 安装与运行

```bash
# 安装依赖（推荐 Bun）
bun install

# 启动开发服务器
bun dev          # 默认 http://localhost:5173

# 类型检查 + 生产构建
bun build        # 产物输出到 dist/

# 预览构建产物
bun preview

# 代码检查
bun lint
```

> 说明：仓库使用 `bun.lock` 锁定依赖。如需使用 npm，可运行 `npm install`，但 `package-lock.json` 当前未纳入版本控制。

## 项目约定

### 目录与分层

代码遵循「组件 / 服务 / 功能 / 类型 / 工具」分层，详见 `docs/架构说明.md`：

- `src/components/`：纯 UI 组件，负责渲染与交互，不承载业务流程
- `src/services/`：业务逻辑层（分析、迁移、历史），与 UI 解耦
- `src/features/`：跨组件的场景逻辑聚合（文件选择、迁移向导）
- `src/types/`：共享 TypeScript 类型定义
- `src/constants/`：默认配置与常量
- `src/utils/`：格式化、日志、本地存储等工具函数

### 编码规范

- TypeScript `strict` 模式，避免使用 `any`
- 关键逻辑添加中文注释；函数超过 20 行考虑拆分
- 源文件超过 200 行时按职责拆分（UI 组件、hooks、工具、类型、常量分别成文件）
- 用户可见文案统一通过 `src/translations.ts` 翻译键引用，不硬编码
- 文件头部标注路径与版本号（如 `// src/services/xxx.ts vX.Y.Z`）

### 提交规范

提交信息格式：`<type>: <description>`

| type | 含义 |
|------|------|
| feat | 新增功能 |
| fix | 修复缺陷 |
| docs | 文档更新 |
| refactor | 代码重构 |
| style | 代码风格调整 |
| test | 测试相关 |
| chore | 构建/依赖/配置变更 |
| perf | 性能优化 |

每次提交若涉及版本变更，应在正文或页脚标注新版本号。

### 版本管理

- 采用 SemVer；任意修改至少升级一次 patch 版本（`x.y.Z → x.y.Z+1`）
- 版本单一来源：`package.json` 的 `version`、`README.md` 徽章、`openspec/changes/CHANGELOG.md`
- 被改动且含头注释的源文件，同步更新其头注释版本号；未改动文件不得批量刷写

## 调试与常见问题

- **开发服务器无法启动**：确认端口 5173 未被占用，或检查 `vite.config.ts` 中的 `server` 配置
- **构建失败**：优先执行 `bun lint` 与 `tsc` 类型检查定位错误
- **翻译缺失**：新增界面文案时同步在 `src/translations.ts` 的中英文对象中添加键

## 测试

当前仓库尚未包含自动化测试（`package.json` 中虽声明 `test` 脚本与 Vitest 依赖，但暂无测试文件）。后续计划补充 services 层（分析/迁移逻辑）的单元测试。

## 贡献流程

1. Fork 仓库并基于 `main` 创建特性分支（`feature/*`）
2. 保持 lint 与 build 通过
3. 提交信息遵循上述规范
4. 发起 PR 到 `main`，描述变更内容、动机与测试说明
