# WinLink 架构说明

本文档说明 WinLink 的前端架构、分层职责与关键数据流，帮助开发者理解代码组织方式。当前版本为 Web 前端原型，迁移与文件操作以模拟方式实现。

## 总体架构

WinLink 采用**分层架构**，将界面渲染、业务流程、领域模型与工具能力解耦：

```
┌─────────────────────────────────────────────┐
│                  UI 层 (components/)           │
│  AppList / DriveSelector / WizardStep* / Modal │
└───────────────┬───────────────┬───────────────┘
                │               │
        ┌───────▼──────┐ ┌──────▼───────┐
        │ 功能层        │ │ 服务层        │
        │ (features/)  │ │ (services/)  │
        │ 文件选择/迁移 │ │ 分析/迁移/历史│
        └───────┬──────┘ └──────┬───────┘
                │               │
        ┌───────▼──────┐ ┌──────▼───────┐
        │ 类型层        │ │ 工具层        │
        │ (types/)    │ │ (utils/)    │
        └──────────────┘ └──────────────┘
                │
        ┌───────▼──────┐
        │ 常量层        │
        │ (constants/) │
        └──────────────┘
```

## 分层职责

### UI 层（`src/components/`）

负责界面渲染与用户交互，不直接处理业务流程：

- `AppList.tsx`：应用文件夹列表与操作入口
- `DriveSelector.tsx`：系统盘 / 目标盘选择
- `LanguageToggle.tsx`：中英文切换
- `ProgressBar.tsx`：通用进度条
- `MigrationModal.tsx` / `ResultModal.tsx`：迁移进度与分析结果弹窗
- `WizardStep*.tsx`：迁移向导各步骤组件

### 功能层（`src/features/`）

按业务场景聚合跨组件逻辑：

- `fileSelection/`：文件 / 文件夹选择相关逻辑与组件
- `migration/`：迁移向导相关逻辑与组件

### 服务层（`src/services/`）

承载核心业务逻辑，与 UI 解耦、便于复用与（未来）测试：

- `geminiService.ts`：**离线本地规则**安全性分析（非外部 AI 服务）
  - `getOfflineAnalysis(folderPath, folderName)`：依据路径关键字判定风险等级并给出安全评分与建议
  - `analyzeFolderSafety`：先查分析历史缓存，后回退离线分析
- `migrationService.ts`：迁移流程编排（当前为**模拟实现**）
  - 步骤状态机：`IDLE → MKDIR → ROBOCOPY → MKLINK → (VERIFYING) → COMPLETED`
  - 回滚流程：`CLEANING`
  - 支持单个 / 批量（串行或并行）迁移、取消（`AbortController`）、回滚
  - 暂停 / 恢复当前返回 `false`（暂不支持）
- `analysisHistoryService.ts`：分析结果缓存与历史管理

### 类型层（`src/types/`）

统一的领域模型类型，跨模块复用：

- `AppFolder`：应用文件夹（名称、路径、大小、状态）
- `MigrationConfig`：迁移配置（目标盘、是否并行、是否验证等）
- `AnalysisResult`：分析结果（风险等级、评分、建议、警告）
- `MoveStep` / `MigrationStatus`：迁移步骤与状态枚举

### 常量层（`src/constants/`）

集中存放默认配置与应用常量，如迁移默认参数、风险等级阈值。

### 工具层（`src/utils/`）

通用的格式化、日志、本地存储等纯函数。

## 关键数据流

### 分析流程

1. 用户在 `AppList` 选择文件夹 → 调用 `features` 或 `App` 中的处理函数
2. 处理函数调用 `geminiService.analyzeFolderSafety`
3. 服务先查 `analysisHistoryService` 缓存（可关闭），否则执行 `getOfflineAnalysis`
4. 结果写入历史并在 `ResultModal` 展示

### 迁移流程

1. 向导（`features/migration` + `WizardStep*`）收集目标盘与配置
2. 调用 `migrationService` 启动迁移，按 `MoveStep` 状态机推进
3. 实时进度通过回调回传 UI（`MigrationModal` 进度条）
4. 支持取消（`AbortController`）与回滚（逆序清理）

## 国际化

- 所有用户可见文案通过 `src/translations.ts` 的翻译键引用
- `LanguageToggle` 切换 `zh` / `en`，组件按当前语言取值
- 新增界面文案须同步补充中英文键，避免硬编码

## 状态管理

- 界面级上下文状态在根组件 `App.tsx` 中集中管理（当前为 Web 原型，未引入 Redux/Zustand 等全局状态库）
- 跨组件共享的状态通过 props 或轻量上下文传递
