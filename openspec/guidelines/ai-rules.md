# WinLink AI 助手规则

## 概述

本文档为参与 WinLink 项目的 AI 编码助手（如 CodeBuddy、Copilot 等）提供统一的行为准则与约束。详细的团队级规则见仓库根目录 `AGENTS.md`。

## 核心原则

1. **文档与代码一致**：生成的文档内容必须与实际代码实现相符，禁止虚构尚未实现的功能、服务或配置（如未接入的第三方 API、未引入的框架）。
2. **以源码为准**：当文档与代码冲突时，以源码为事实来源；修正文档而非臆造代码。
3. **最小版本号升级**：每次修改（新增/删除/修改文档或代码）需同步升级最小版本号（见根 `README.md` 与 `openspec/changes/CHANGELOG.md`）。
4. **提交信息规范**：遵循 `<type>: <description>` 格式（feat / fix / docs / refactor / style / test / chore / perf）。
5. **不触碰密钥**：代码与日志中不得包含任何密钥、Token 或敏感凭据。

## 编码约束

- TypeScript 开启 `strict` 模式，避免 `any` 类型。
- 源文件超过 200 行时按职责拆分为更小模块（UI 组件、hooks、工具函数、类型、常量分别成文件）。
- 关键逻辑添加中文注释；函数超过 20 行考虑拆分。
- 国际化文本提取到翻译文件（`src/translations.ts`），不硬编码用户可见文案。
- 正确捕获并处理 Promise 异常，避免未处理的 reject。

## 文件头与版本

- 源文件头部标注路径与版本号（形如 `// src/services/xxx.ts vX.Y.Z`）。
- 仅被本次改动的文件才更新其头注释版本号；禁止批量刷写无关文件。
- 全局展示版本单一来源：`package.json` 的 `version`、根 `README.md` 徽章、`openspec/changes/CHANGELOG.md`。

## 工作模式

- **规划模式**：5+ 文件变更、新增依赖或架构调整时，先输出计划/规格再实现。
- **直接模式**：3 文件以内的拼写修复、文档更新直接执行。
- **并行模式**：多项独立操作批量并行执行。

## 质量门禁

- 提交前确保 `bun lint` 与 `bun build` 通过。
- 无 `console.log` / `debugger` 残留语句。
- 文档变更需在 `CHANGELOG.md` 追加对应版本小节。
